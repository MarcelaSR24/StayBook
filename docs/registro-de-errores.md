# Registro de errores y defectos - StayBook

**Responsable:** Stiven - Líder de pruebas.

**Estado:** Preparación inicial.

## 1. Objetivo

Documentar los errores encontrados durante las pruebas de la plataforma StayBook, facilitando su seguimiento y corrección por parte del equipo de desarrollo.

## 2. Clasificación de severidad

| Nivel | Descripción |
|---|---|
| Crítica | Impide utilizar una funcionalidad esencial o compromete gravemente el sistema |
| Alta | Afecta una funcionalidad importante |
| Media | Genera problemas, pero existe una alternativa para continuar |
| Baja | Error visual o detalle menor |

## 3. Registro de defectos

| ID | Fecha | Módulo | Descripción | Severidad | Estado |
|---|---|---|---|---|---|
| DEF-001 | Pendiente | Pendiente | Sin defectos registrados | Pendiente | No aplica |

## 4. Información que debe registrarse por cada defecto

- Identificador del defecto.
- Fecha en que se encontró.
- Módulo afectado.
- Caso de prueba relacionado.
- Pasos para reproducir el error.
- Resultado esperado.
- Resultado obtenido.
- Severidad.
- Evidencia (captura o archivo).
- Responsable de corregirlo.
- Estado de seguimiento.

## 5. Estados de los defectos

- Nuevo: error identificado.
- Reportado: comunicado al equipo.
- En corrección: desarrollo está trabajando en él.
- Corregido: el equipo informa que fue solucionado.
- Verificado: se repitió la prueba y se confirmó la solución.
- Reabierto: el error continúa o volvió a aparecer.

## 6. Observaciones

Este registro se actualizará cuando comiencen las pruebas reales de StayBook. No se registrarán defectos ficticios ni se marcarán errores como corregidos sin verificarlos.
